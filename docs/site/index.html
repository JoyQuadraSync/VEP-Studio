Product principles

Engineered for explicit, inspectable execution

VEP Studio combines typed event infrastructure with a deterministic workflow model. Its boundaries are designed before capabilities are expanded.

  • Event-driven
  • Strongly typed
  • Deterministic
  • Architecture-first
  • Built with TypeScript
  • Designed to evolve toward workflow automation and governed AI agents

AI-agent participation is a future direction and is not implemented in v0.3.0.

Available in v0.3.0

Current capabilities

The current release establishes the event, definition, runtime, and decision foundations of the platform.

01

Strongly Typed Events

Typed event maps and payload contracts protect the event pipeline at compile time.

02

Concurrent EventBus

Named subscribers run concurrently with isolated failures and ordered results.

03

Runtime Foundation

Explicit publication results, subscriber results, stable identities, and duration metadata.

04

Workflow Definitions

Immutable, versioned process graphs use dotted IDs and declarative operations.

05

Immutable Workflow Runtime

Each transition returns a new WorkflowExecution snapshot instead of mutating runtime state.

06

Operation Registry

Stable operation identifiers resolve to synchronous or asynchronous runtime handlers.

07

Decision Steps

Decision nodes support multiple conditional transitions and one explicit default branch.

08

Declarative Conditions

Serializable edge conditions use a deliberately small, deterministic expression language.

09

Deterministic Branch Selection

All eligible conditions are evaluated; ambiguous and unmatched branches fail explicitly.

Architecture overview

Separate event delivery from workflow control flow

Event publication and workflow execution cooperate through explicit boundaries, but they do not share mutable state or control-flow ownership.
